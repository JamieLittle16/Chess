V15 is a measured production milestone, not a bundle of unqualified search ideas. This document records the accepted Rust change, the full-generation calibration, rejected research lanes, and the separate Python competition-submission track.

## Accepted Rust production change over V14

Production V15 changes quiescence search so the local tactical qsearch ceiling may not terminate while the side to move is still in check. Checked nodes continue through legal evasions until the position reaches a non-check node or the global search-ply guard. The ordinary local qsearch ceiling remains unchanged for non-check nodes.

Baseline: exact accepted V14 production `f76d9a06e18b914cbc0a7a98bb465cdc66e4fcf9`.

Qualification run: GitHub Actions `34237325229` (`M7 V15 qsearch check-evasion v2 screen`).

| Protocol | W | D | L | Relative Elo |
| --- | ---: | ---: | ---: | ---: |
| 100 paired fixed-node games, 25k nodes/move | 26 | 58 | 16 | `+34.86 +/- 39.08` |
| 100 paired equal-time games, `1+0.01` | 23 | 59 | 18 | `+17.39 +/- 40.28` |

Fixed-node throughput was effectively unchanged. The production materialization passed fmt, clippy with `-D warnings`, the complete release workspace test suite, explicit checked/non-check qsearch-ceiling tests, and the deterministic reference benchmark.

## Rejected Rust V15 research lanes

The following ideas were tested on the mature V14 baseline and are intentionally not part of V15 production:

- Gestalt-gated verified null move v4: `-10.43 +/- 38.85` Elo at fixed nodes and `+3.48 +/- 39.50` at equal time; no compelling playing gain.
- TT singular extension v1: `-27.85 +/- 41.73` Elo at fixed nodes and `-31.35 +/- 44.41` at equal time.
- two-ply continuation history: exactly neutral at fixed nodes and `-27.85 +/- 38.14` at equal time.
- multi-context correction history: `-27.85 +/- 42.87` at fixed nodes and `-52.51 +/- 44.59` at equal time.
- raw Viridithas v16 Perseverance evaluator: strong equal-node signal but far too expensive at runtime. It evaluated roughly 5.64x slower than Gestalt, produced about `+45.42 +/- 42.71` Elo at equal nodes, but approximately `-168.40 +/- 57.81` Elo at equal time. It is therefore a teacher/compression research asset, not a production evaluator.

Rejected mechanisms remain useful experimental evidence. They should not be silently reintroduced or retuned without a new hypothesis explaining why the previous failure mode is no longer applicable.

## Python competition track

The Python competition engine is a separate runtime target. Packaged V14 already has the semantic equivalent of the Rust checked-qsearch ceiling correction, so the Rust V15 fix does not provide a new Python delta by itself.

### Rejected direct-check family

Direct quiet bishop/rook/queen checks at qsearch root showed a genuine fixed-node signal but failed to convert under the real competition clock.

- Broad implementation: about `+25.38` naive Elo over 96 equal-node games, but only about `0.848x` V14 throughput.
- Lean direct-slider implementation: the same `51.5/96` equal-node score (about `+25.38` naive Elo) at `0.92591x` throughput.
- Two independent lean implementations were deterministically equivalent on 64/64 roots (move, score, depth and nodes all identical).
- Larger disjoint real-API timed confirmation: `30.5/64` (47.66%, about `-16.3` naive Elo).
- Quiet-only refinement: `33.5/64` at equal nodes (52.34%, about `+16.3` naive Elo), `0.9637x` throughput, but only `27/64` (42.19%, about `-54.7` naive Elo) in its real-API timed gate.

The direct-check family is therefore rejected for the competition package despite its equal-node tactical signal.

### Current Search-v2 transfer programme

The strongest current Python search hypothesis is a coherent port of the accepted Rust Search-v2 history machinery rather than another isolated history heuristic. Packaged V14 already has PVS, killers, verified LMR and conservative shallow pruning, but lacks the mature side-specific main history + one-ply continuation history + history-conditioned LMR coupling.

The current candidate uses:

- 384 move contexts (`6 piece kinds x 64 destinations`);
- side-specific `2 x 384` main history;
- `384 x 384` one-ply continuation history;
- Rust-style bounded gravity updates with limit 16,384 and max update 2,048;
- the accepted `+4096 / -4096` history-conditioned LMR thresholds;
- quiet scout-node evidence only, with positive cutoff and half-strength negative updates;
- history lifetime of one top-level search, persisting across iterative-deepening iterations.

The first runtime probe retained about `0.922x` V14 throughput. Fresh equal-node qualification and learned-pruning companion screens are in progress; neither is accepted until it survives a real `agent.get_move(fen, time_left_ms)` confirmation.

## Evaluator direction for Python V15

The large Perseverance experiment demonstrates that richer evaluation contains useful chess signal but cannot simply be copied into a Python/Numba leaf evaluator. The preferred transfer path is distillation into the existing compact incremental student family:

- preserve H64/H96-scale inference rather than a 2048-wide runtime accumulator;
- use the strongest available NNRU/Perseverance-style model as teacher signal;
- investigate richer king-aware or king-bucketed relative features where they improve information per runtime operation;
- quantize for the exact competition runtime;
- select candidates by game strength per unit wall time, not validation loss alone.

Any final Python V15 package must be reconstructed from the exact accepted V14 artifact and must pass competition-API legality, throughput, fresh equal-node, and fresh equal-time qualification before submission.
